# Discourse RSC

RiversideCoin 的原生 Discourse 插件，提供行情交易、赛事预测、事件预测、排行榜、RSC 钱包、红包与帖子打赏。使用论坛登录、PostgreSQL、Sidekiq 和站内通知，不依赖旧独立 RSC 服务。

## 数据与状态

标的以 `discourse_rsc_instruments` 为准：`active` 表示是否启用，`name` 是名称，`symbol` 是稳定的内部标识，`provider_symbol` 是行情接口代码。显示代码、交易所和交易时段保存在该行的 `metadata`。收录状态与开市、报价时效、是否允许成交分别判断。

不再保留固定旧目录或“哪些已上市”的 Markdown 清单，也不提供从旧清单重新导入的管理操作。新增标的通过在线校验或管理员维护写入数据库；停用不删除历史关联。旧归档仅用于历史查询与显式迁移，不参与日常目录和交易时段的读取。数据库备份包含标的状态和元数据。

`discourse_rsc_market_requests` 保存用户添加请求和校验结果。`POST /rsc/market-requests.json` 自动校验支持的行情品种，成功返回 `id`、`status: approved` 和 `instrument_id`；失败保留中文原因供重试。后台依据实际标的显示“已收录／已停用／校验失败／待校验”，原始申请状态留作历史，不代表当前交易资格。收录和重试无需填写审批原因。

事件预测的题目、加入申请及内容审核分别存入 `discourse_rsc_forecast_markets`、`discourse_rsc_forecast_requests`，继续按其内容审核规则处理，不因取消行情标的审批而自动放行。

## 页面与维护

- `/rsc/market`：行情、持仓、下单、委托和品种查找；`/rsc` 默认进入行情交易。
- `/rsc/sports`、`/rsc/forecast`：赛事预测与事件预测。
- `/rsc/leaderboard`、`/rsc/account`：排行榜与 RSC 钱包。
- `/rsc/admin`：数据库目录、收录记录、资金、奖励、赛果与审计管理。
- `/rsc/packets/:token`：红包分享与领取。

插件通过 Git 安装，数据库迁移随论坛部署执行。使用组由 `rsc_allowed_groups` 控制，管理组由 `rsc_admin_groups` 控制，站点管理员具有管理权限。初次安装默认关闭且只读；配置应以论坛站点设置为准，不以旧上线记录推断当前开关。

资金按 18 位整数最小单位计算，使用复式账本、事务锁和幂等请求。请求使用论坛会话与 CSRF；`request_id` 为 8–100 位字母、数字、下划线或连字符。添加标的不会创建订单或改变用户余额。

行情更新按持仓、挂单和浏览需求调度，闲置标的使用有上限的后台轮询；来源限流、报价时效和异常复核继续生效。实时行情、活动、通知和内容审核开关均以数据库设置为准。

### 外汇异常报价复核

所有外汇的新报价在写入成交/估值快照前经过 `ForexQuoteGuard`。变化达到 0.1% 触发复核，不因报价间隔变长而放宽；跨源一致性带为 0.05%。阈值只触发复核，不直接认定真实波动为错误。

Yahoo 是主源：新鲜报价相对已接受价格变化不足 0.1% 时直接接受，不因旧备用样本的差异进入隔离，也可从旧版仅由跨源分歧造成的隔离中恢复。达到阈值的可疑报价不覆盖接受价、不写入接受历史、不用于成交或强平；重复出现不能自行解除隔离，仍须跨源核验或返回正常范围。备用源连续三次独立时间戳、跨度至少 120 秒且价格相近时，可以接管；Yahoo 恢复新鲜且正常的报价后回到主源。

Twelve Data 仅在主源过期/不可用的交易兜底或异常跳价复核中使用，不再主动抽查正常 Yahoo 行情。已有有效且通过核验的备用报价优先复用；主源恢复正常即停止备用接管。分钟采样保留真实时间戳，最多允许 180 秒源数据年龄，接收时间仍须在 120 秒内。每个标的最多每 60 秒复核，备用源共享缓存、失败退避、8 秒全局调用间隔和每日 750 次预算。配额不足或报价不可信时继续等待，不按旧价假成交。此策略不主动识别未触发跳价的持续缓慢偏差。

图表和报价共用按标的/周期加锁的 15 秒 Yahoo 快照缓存，日内图读取新快照时同时更新交易报价。外汇日内图仅展示接受的报价；其他周期是标明单位的供应商参考历史。闭市后通过现有队列分散补取收盘数据，每个标的最多每 5 分钟一次，取得收盘 20 分钟后的观察即停止。交易仍遵守真实开市时间。

外汇在北京时间工作日 08:00–09:00 增加一轮 Yahoo 主源补刷，优先待成交委托和持仓，每分钟最多扫描 3 个标的，单批最多启动 12 秒内的请求。共享报价缓存、限速、退避和尖刺复核；已有新鲜报价直接复用，不强制调用备用源。每日进度保存在 Redis，任务重启继续剩余标的；失败由正常轮询继续重试，周末闭市、只读或停用时跳过。此任务不保证上游产生新价格，也不改变交易时间。

非延迟外汇开仓和平仓使用当前新鲜且通过核验的报价直接成交，不要求源时间晚于下单时间；旧版待成交开仓也采用此规则。下单已有本版核验通过的有效快照时直接复用，不等待网络刷新；报价仍由后台正常更新，成交事务内再次检查时效。即时开仓按实际保证金加手续费预留，不加待成交订单的 5% 缓冲。报价过期或待核验时不能开仓，平仓可进入等待有效报价的队列。真实延迟行情继续等待提交后的来源报价。

外汇成交保存来源、原汇率、源时间、接收时间、复核方法及成交时间。此保护不能保证识别所有供应商错误，不自动改写旧成交或补偿余额。

### 虚拟币成交与任务恢复

虚拟币开仓和平仓使用当前新鲜有效报价直接成交，返回 `execution_mode=immediate`，不再要求下一笔源时间或额外开仓等待。已排队的旧订单也不再等待旧 `execute_at`，但仍检查过期、价差保护、余额和风控；不改历史成交。即时开仓的预留与成交共用一次计算的执行价；数量估算使用买入/卖出价，无待成交 5% 缓冲。若额外滑点配置启用或无可靠买卖盘口，预览按原规则的最大滑点保守估算，实际订单只抽取一次滑点。

交易成功立即反馈并释放提交状态，余额/持仓异步刷新且不额外拉取供应商行情。旧请求不能覆盖较新的状态；后续刷新失败不会误报成交失败，网络未知结果重试仍沿用原请求号。

行情调度检查 Sidekiq 执行中、普通队列、重试和定时队列。仅在同一占用标记连续两次无人持有、间隔至少 30 秒时，按原值比对释放并重新调度；每种任务最多每 15 秒扫描一次。全量刷新共享锁同时检查人工刷新任务，避免误删活跃锁；定时全量任务不阻塞等待此锁。恢复沿用原调度频率和供应商限额，不集中刷新全站。

### 前端状态边界

行情工作台、钱包表单和赛事预测分别由 `rsc-dashboard`、`rsc-wallet-panel`、`rsc-sports-panel` 管理界面状态。提交仍共用父组件的请求编号与成功反馈，成交后只刷新账户状态；旧请求及离开页面后的响应不会覆盖新状态。钱包和赛事草稿不会混入行情交易状态。

`test/order-feedback-test.mjs` 检查立即反馈、后台刷新、过期响应抑制和相同请求编号重试。

行情委托只要仍为 `pending` 即可撤销，包括延迟行情开仓和平仓，不设提交后 10 秒截止。撤单和成交共用事务锁，先完成者生效；撤单全额退回预占资金且不收费，同一请求重复提交不会重复退款。已成交订单不能撤销。接口保留 `cancel_at=created_at`、`cancel_until=null` 兼容旧客户端，`can_cancel` 由待成交状态决定。

股票提交复用仍有效的报价。轮询优先待成交委托，其次已有持仓，获取报价后立即检查成交；延迟委托以 `source_time > created_at` 为准，不再额外等待估计的 `execute_at`。午休或收盘后送达的盘中有效报价可用于处理已有委托和仓位保护，但不能在休市时新建委托，也不会放宽报价有效期。Yahoo 未明确标注延迟时，仅保留同一交易时段已经测得的延迟用于收盘后的有效报价；不会把昨日收盘价当作实时价。

美股备用配置 `rsc_us_stock_fallback_enabled` 默认关闭，确认 Twelve Data 对外数据权限后开启。仅 Yahoo 美股主源失效的交易请求或待成交处理会调用 `/quote?interval=1min`，与外汇共用每日 750 次上限和 8 秒请求间隔，缓存 60 秒、失败退避 90 秒。校验标的、USD 币种、开市状态和原始时间戳，失败保留原行情；不改动持仓成本。国际股票不会尝试此免费美股备用源。

兼容当前数据库结构的发布使用 `script/deploy-blue-green.py --image IMAGE --commit FULL_SHA --compatible-schema`（root，先加 `--check` 检查计划）。脚本根据 Nginx 上游自动选择 A/B 槽位，保持旧容器服务直到新容器通过应用健康检查、Git 版本和新旧前端资源检查，再平滑切换 Nginx，排空旧请求后停止旧容器。新镜像需保留前一版静态资源；有不兼容数据库迁移的更新不能使用此模式。旧容器尚在排空时脚本保留其运行，不强制断开长请求。

### 保护价保存与外汇核验队列

已有持仓的止盈止损保存、修改和清除不再请求行情。报价过期、缺失或待核验时可先保存，返回 `waiting_quote=true`；仓位归属、冻结钱包、止盈盈利边界、止损强平边界及两个保护价的方向关系仍检查。有效现价存在时继续检查与现价的关系。保存不成交、不收费；触发平仓仍由原来的报价有效性和交易时段检查控制。

外汇待核验标的使用 Redis 共享队列，单个标的最多占用四分钟复核机会，以原来的采样间隔取得独立样本；超时轮转，成功移出队列。快轮询每轮最多补查一个待核验标的；有持仓、待成交委托或最近十分钟有人查看/尝试交易的标的可继续核验，无人关注的目录标的不消耗备用额度。备用源忙时较快重试，失败退避，日额度用完等待 UTC 日期重置；页面请求不会清除退避。仍沿用原有每日额度、全局限速和价格核验规则，不把等待超时或重复时间戳当成有效报价。

回归覆盖：`test/protection_without_quote_test.rb`、`test/forex_review_queue_test.rb`；测试仅在隔离论坛数据库执行。

备用行情用量通过管理员接口 `market_health.fallback_usage` 或 `DiscourseRsc::FallbackBudget.report(date)` 查询，按 UTC 日期、标的、触发操作、原因和结果汇总，保留 14 天。`total_reserved` 兼容旧总计，细分 `rows` 仅从 `tracked_since` 开始记录；`requests` 包含已尝试但超时/失败的请求，不等同于供应商账单。缓存命中不增加请求数；供应商全局冷却/排队在 HTTP 前拦截时退还预扣额度，并记为 `not_sent`。不记录密钥、请求 URL 或用户身份。

没有持仓/委托、仅浏览触发的备用核验每天合计最多使用 60 次（包含在总额 750 内），不限制主源刷新；明确下单/平仓及其十分钟内的后续核验、已有持仓的风控刷新不受这个浏览预算限制，仍遵守总额和全局 8 秒间隔。连续备用请求失败依次退避 90/180/300 秒，成功后复位。持仓持续依赖备用源仍会持续消耗额度，不能把免费备用源当作无限全天主源，也不延长成交报价有效期。

额度回归：`test/fallback_budget_test.rb` 覆盖缓存复用归因、浏览预算与交易隔离、并发共享限速、未发出请求退款、真实失败计数和递增退避。
