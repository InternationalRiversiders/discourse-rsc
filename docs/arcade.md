# 休闲挑战

`/rsc/games` 分为休闲挑战与幸运游戏，首次默认休闲挑战，记住上次栏目；流水深链仍直接进入幸运游戏记录。原有游戏、3D 场景、彩票不改规则。

七款原创轻量实现：2048、方块堆叠、贪吃蛇、河畔飞鸟、六角消除、打砖块、合成大河畔。没有复制第三方美术或无许可代码。经典玩法使用自有可复核规则；六角消除为同一边连续三个同色块消除。

## 协议

- `POST /rsc/arcade/start`：会员身份、功能开关、钱包状态检查；同一用户同一游戏最多一局在玩。创建重试返回原局，普通重新进入恢复有效局。
- `POST /rsc/arcade/:id/advance`：`version, request_id, frames, events, finish`。每批最多 180 帧、360 个输入，事件为 `[批内帧号, 指令]`。按固定 60Hz 逻辑帧重算；2048 每批最多一步。
- 操作由服务器从已确认状态重算，不接收客户端分数或坐标状态。随机源使用 SecureRandom，无完整种子下发；2048 不返回任何未来随机数，其余最多预取 20 个随机值。预取窗可被策略程序读取，这是允许范围。
- 前后端共用 `arcade-core.js`。服务端 MiniRacer 设内存和执行超时，不执行客户端代码。整数物理避免渲染帧率影响碰撞；每个周期版本需固定，规则升级需先结束或兼容旧局。
- 行锁、状态版本、请求摘要保证重复请求只提交一次；断网重试同一请求，也可重新读取服务端已保存进度。原始随机窗与分段输入保留在服务端，能离线重放；不通过 API 暴露完整记录。
- 实时游戏每约 2 秒后台同步，等待响应时继续运行并记录最多 180 帧的未发送尾段。收到确认后用服务端状态和尾段操作复算，不覆盖期间的操作。超过缓存或随机窗口耗尽才暂停等待；失败保留原请求和尾段。结束/暂停会排空待保存操作。
- 2048 的未来方块仍只在服务端生成；等待时缓存滑动，确认后依次处理。输入请求限流按其一步一请求的特点单独设置为每分钟 600 次，其余游戏批量同步保持每分钟 180 次。前端按下即响应，长按重复与键盘释放不依赖网络同步。
- 每局最长 2 小时，不能跨越本期截止；每款另有有限步数、方块数或逻辑帧上限，限制计算成本。允许机器人和加速策略，不以真人耗时作排名依据。

## 排名与奖励

北京时间周日 20:00 换期，每人每款最高有效完成成绩，同分并列。冻结钱包、停用/封禁用户及管理员不参加奖励榜。榜单缓存 20 秒。

本次上线 `rsc_arcade_rewards_enabled=false`，免费、不扣款、不发 RSC。每期开启时快照奖金设置，之后更改只影响新一期。预备配置为每款前五 100/60/40/25/15 RSC；并列共享占据名次的总奖金。结算使用统一 RSC Ledger，每期仅执行一次；极小整数尾数不增发。启用奖励前须同步调整前端说明并复核活动预算。

## 发布

仅新增两张表，旧版本可与新表共存。先在隔离数据库迁移和测试，发布镜像完成全部前端编译；从备用镜像运行一次迁移，再按 A/B 流程启动、验证、切流量、排空。回滚只切回旧 Web，不删除已产生的新表或成绩。
