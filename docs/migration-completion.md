## 运行设置

基础开关仍是 `rsc_enabled`、`rsc_native_trial_enabled`，默认关闭。数据源由 `rsc_market_data_enabled`、`rsc_sports_data_enabled` 分别控制；Twelve Data 密钥仅在服务端设置。`rsc_twelve_data_delay_seconds` 必须按订阅套餐填写。高风险另设 `rsc_high_risk_enabled`，默认关闭。

定时任务使用 Discourse/Sidekiq。行情 REST 同步按分钟轮询、赛事按五分钟轮询，页面每 15 秒刷新；本轮没有移植旧 Coinbase WebSocket 常驻进程。30–90 秒的开仓等待是最早执行时间，实际成交受后台轮询影响。默认每轮最多同步 100 个标的，最多四路并发、同源每秒四次请求、45 秒内停止领取新任务；批量导入整个目录不等于所有标的都获得实时行情，过期报价会阻止交易。大目录上线前必须按数据源配额和实际负载验收。

Yahoo 和 ESPN 延续旧系统的公共接口，不能视为有可用性保证的正式数据合同。Coinbase/Kraken/OKX 历史数据受供应商周期和数量限制，图表显示实际返回的时间范围。非美元 K 线显示原币，不把当前汇率伪装成历史汇率。OKX 的 USDT 标的沿用旧系统虚拟市场的 USDT/RSC 数值约定。

ESPN 加时/点球比赛只在获得上下半场分数证据后自动结算；证据不足时等待管理员核实。已付款后出现供应商赛果更正只记录审计，不自动扣回用户资金。管理员可通过有原因的资产调整处理核实后的差额。

## 导入操作与核对

在旧库的只读快照上运行（文件名不能已存在）：

```sh
python3 script/export_legacy.py /path/to/legacy.sqlite /private/rsc-export.json
```

脚本只读打开 SQLite，在一致性事务中导出，输出权限 0600，保留金额字符串，排除游戏表；发现未结算游戏资金会拒绝。输出包含用户和账务资料，不能放入公开目录或 Git。

将导出文件放入**隔离测试论坛**后，执行完整演练：

```sh
bundle exec rails runner plugins/discourse-rsc/script/import_legacy.rb /private/rsc-export.json
```

默认执行全部导入与数据库延迟约束检查后回滚，返回逐类资金总额、行数及 SHA-256。钱包、持仓保证金、待结算预测本金、红包余款独立计入并核对；所有会计分录总和必须为零。导入目标必须没有 RSC 账本及业务记录，用户 ID 必须存在，有用户名时也核对身份，不能静默丢弃账户。

演练验收后，在停用旧写入和旧奖励任务、备份两端数据、停用新插件的切换窗口，才使用以下方式正式导入：

```sh
RSC_IMPORT_APPLY=1 RSC_IMPORT_SHA256=<演练返回的校验和> \
  bundle exec rails runner plugins/discourse-rsc/script/import_legacy.rb /private/rsc-export.json
```

正式导入还要求 `rsc_enabled=false`。本次没有执行生产导入或上述切换。

关键约定：

- 旧挂单只作“已取消”导入。其预留金额原本仍在钱包余额中，不能再次退款。
- 旧流水不重放到新钱包；生成可核对的期初分录，旧流水归档并可查询。
- 旧持仓和预测继续存在，报价必须由新数据源重新获取；导入不把旧报价标成新报价。
- 未领取红包保留公开 token、已领取人和剩余分配；分配金额不吻合时整批失败。
- 已成功发放的每日奖励导入幂等记录，避免自动补偿再次发放。
- 旧期段业绩表保留原始归档；已恢复有有效本金起点的历史资金流收益观测节点，不补造每日净值或切换后的连续收益。
- 世界杯活动已增加原生检查、缺失返利/徽章补发与可选定时任务；继承 206 人的历史已发标记，真实快照待补发为 0。
- 先校验论坛账号，再分批归档历史和奖励防重记录。缺失论坛账号仍会阻止完整导入，不能自动创建或猜测资金接收人。
- 期初资金每批最多 100 个接收账户，经同一个账本服务写入平衡分录；所有批次仍处于同一导入事务内，任何后续错误会全部回滚。每批分录保留源文件哈希与账户来源映射，不产生历史通知。
- 遇到未列入清单的非棋牌游戏业务表时，导出会拒绝并列出表名，要求先核对覆盖范围，避免遗漏新增业务。
- 带有 `rehearsal_subset` 标记的排查用子集只允许在指定的隔离数据库运行，不能当作正式生产导入文件。

隔离环境中完成导入后，可逐条核对全部历史、逐钱包余额、持仓保证金、预测本金、红包及奖励防重标记：

```sh
bundle exec rails runner plugins/discourse-rsc/script/verify_legacy.rb /private/rsc-export.json
```

此验证脚本要求 `RSC_DISPOSABLE_CONTAINER=1` 且数据库为 `rsc_discourse_smoke`，不修改记录，不进行行情同步、奖励发放或通知投递。

## 验证边界

隔离测试覆盖账本并发与防重、冻结结算、风控、行情源失败与过期、真实公开响应格式、足球常规时间判定、管理员接口鉴权、历史查询归属、钱包/持仓/预测/红包导入及回滚对账。当前 61 个后端测试、322 项断言通过。浏览器覆盖原生页面、下单、通知、图表切换、保证金、排行榜、帖子打赏汇总和管理员操作。

这是一轮可运行、可验收的原生实现，不代表已经完成真实全量资产演练、付费行情套餐联调、长期运行或生产接管。棋牌游戏依然按要求排除。

参考接口：[Coinbase](https://docs.cdp.coinbase.com/api-reference/exchange-api/rest-api/products/get-product-trades)、[Twelve Data](https://twelvedata.com/docs)、[Kraken](https://docs.kraken.com/api-reference/market-data/get-ticker-information)、[OKX](https://www.okx.com/docs-v5/en/)。Yahoo/ESPN 的响应兼容性同时用实际公开响应验收。

补充回归覆盖：股票休市/报价不可用时，该仓位不计入可用风险资本，仍允许以充足现金参与虚拟币市场；爆仓跳空后的已实现亏损按实际返还与保证金差额统计，避免排行榜把超出保证金的理论跌幅算成已扣款。
