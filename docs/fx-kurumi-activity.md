# 久留美外汇活动（2026）

活动代码 `fx-kurumi-2026`；默认关闭，部署验证后设置实际开始时间。预计结束时间 `2026-12-17T18:00:00Z`（日本时间 12 月 18 日 03:00），来自每周四、全 12 话的预期排期，尚非官方最终话日期。管理员可在行情交易的“活动榜与规则 → 调整活动结束时间”修改未来截止时间；截止冻结后不能通过该入口重开。

## 交易与统计

- 外汇目录扩充为 27 个币种，新增 BRL/MXN/ZAR/TRY/SEK/NOK/DKK/PLN/CZK/HUF/THB/IDR/MYR/PHP/TWD。列表和品种查找支持国家名、中文币名、英文名、币种代码；沿用每单位外币的 USD/RSC 报价和活动规则。来源可能停更或滞后，目录收录不代表始终可成交，仍检查来源时间和休市。品种别名不会重复建档。
- `rsc_forex_activity_enabled`、`rsc_forex_activity_starts_at`、`rsc_forex_activity_ends_at` 控制活动窗口；时间字符串含时区。`rsc_high_risk_enabled` 仍是高杠杆总开关。
- 活动期间外汇可选 1–100×；活动外汇按钱包可用余额及费用预留开仓，不受 `rsc_high_risk_margin_percent` 限制，也不占用虚拟币额度；活动结束后的存量外汇仓位仍不占用虚拟币额度。外汇不使用虚拟币的冷却或最短持仓时间。
- `rsc_forex_activity_fee_bps` 默认 0，活动免手续费。旧外汇仓位及其加仓保留原费率，不纳入活动。活动降费适用于已有活动仓位及待成交活动单的后续成交；已扣费用不追溯改写。更低费率随活动条目保存，结束后的平仓也沿用。
- 活动外汇开仓等待来源时间晚于提交时间的新报价，待成交期间可撤单。非延迟外汇平仓按最新有效报价直接成交，不再等提交后的下一笔；主动刷新共享 5 秒缓存，来源时间、休市、过期检查保留。存量待成交平仓同样适用。外汇不使用随机滑点或离散价格保护价差。结束或暂停时未成交的活动开仓自动取消并退款；已有仓位不会强制平仓。结束后普通杠杆恢复原规则，已有高杠杆可平仓、补保证金、改止盈止损。
- 日元报价仍是每单位日元折合 RSC；做多 FX:JPY = 看涨日元兑美元，不是做多 USD/JPY。不改旧仓数量或成本。
- 常用六币种 JPY/EUR/GBP/AUD/CAD/CHF 纳入原有活跃行情更新队列，持仓和待成交外汇另有每 15 秒调度的快速队列，每个标的共享 20 秒刷新缓存，优先待成交单并立即检查止盈止损；仍受批次、来源队列、休市和失败退避限制。
- 独立活动条目保留开仓手续费、已实现净盈亏、交易日期和强平标记。未平仓按最近来源报价减预计平仓费估值，现金下限与交易引擎一致；截止时仅选截止前来源报价并冻结。之后加仓、补保证金、平仓均不改已冻结成绩。无可用新来源时使用最后观测值，不伪造时点报价。
- 八枚原生徽章均可用作称号，每人每枚仅授予一次，不额外发 RSC。盈利/亏损里程碑依据活动仓位的不可变资金流水，按成交顺序累计已实现净盈亏（扣除开平仓费用），不含浮动盈亏；历史上跨过门槛后即使回撤或回本，仍可补发。强平仅设首次徽章。

| 徽章 | 条件 |
| --- | --- |
| 我已经完全理解了外汇 | 首次活动开仓 |
| 今天也在盯盘 | 三个 UTC+8 日期开仓或加仓 |
| 强制毕业 | 活动期间首次活动仓位强平 |
| 只是技术性调整 | 累计已实现净盈亏曾 ≤ -100 RSC |
| 这集我看过 | 累计已实现净盈亏曾 ≤ -1,000 RSC |
| 先把学费赚回来 | 累计已实现净盈亏曾 ≥ 100 RSC |
| 离两千万还差一点 | 累计已实现净盈亏曾 ≥ 1,000 RSC |
| 活到完结 | 截止成绩（含未平仓估值）≥ 0，且没有活动强平 |

三枚旧徽章原位改名，保留 ID、授予记录及已选称号。A/B 发布时默认继续使用旧名称；停止旧版本进程后调用 `DiscourseRsc::ForexActivity.award(rename_legacy: true)` 完成改名和历史补发，避免旧任务重新创建旧名称徽章。普通定时任务随后自动处理八项成就。

## API / 原生 App 接入

`GET /rsc/state.json?section=market` 增加 `forex_activity` 摘要；每个标的返回 `max_leverage`、`fx_activity`、`currency_name` 和针对当前用户持仓计算的 `fee_bps`。`market_category=forex` 筛选外汇，旧参数 `fx_activity` 仍兼容并规范为 `forex`。活动期间原外汇分类显示“久留美活动”，到期自动恢复“外汇”，不增加重复分类。

原生 App 需要随版本适配；网页活动上线不等于原生页面已更新：

1. 外汇杠杆上限读 `max_leverage`，不要仅允许 crypto 使用 100×；高于 10× 的下单发送 `high_risk=true`。
2. `forex_confirmation` 与其他非 immediate 模式一样预留新报价缓冲，使用服务端 `fee_bps` 估算数量；`margin_budget_exempt=true` 的活动外汇不叠加 `high_risk.budget.available_margin` 限制，其他高杠杆品种仍要检查该额度。不可仅以余额乘杠杆算满仓。
3. 文案用“看涨/看跌 + currency_name”，保留 FX 单位和小数精度。开仓提交成功为 pending，不表示立即成交；可随时撤销待确认的活动外汇单。`close_execution_mode=immediate` 表示非延迟外汇平仓可直接成交，客户端应按实际返回 status 展示结果。
4. `GET /rsc/forex-activity.json?page=1` 返回 `rows/me/total/page/pages` 及摘要，按需加载，勿秒级轮询。
5. 结束后已持有 100× 仓位的平仓和保护操作仍可用，但不能据持仓杠杆推导可新增 100×。错误 `forex_activity_ended` 提示活动已结束/暂停且本次未成交，可保留表单修改。
6. 本地检查的 App `lib/pages/native_rsc_actions.dart` 仍将非 crypto 上限写为 10；需 App 发布后才能在其原生下单页使用新杠杆。活动期间可先打开论坛网页行情交易。

`POST /rsc/forex-activity/settings.json` 仅管理员可用，参数 `ends_at` 为含时区 ISO 8601；记录审计，不需要新增 API key。

## 发布与回退

新迁移只建立活动统计表，不导入、重算或改写现有资金流水。正常 A/B 构建，容器 YAML 不变。先部署验证、切换并停止旧 Web 进程，再启用活动；旧版本不理解活动费率及 FX 高杠杆，启用后不能直接切回旧镜像。需暂停新活动开仓时关闭活动开关，保留新代码处理已有仓位和平仓。

隔离回归见 `test/forex_activity_test.rb`：新报价、100× 外汇独立于虚拟币额度、费用、幂等、旧仓隔离、部分平仓、到期撤单、截止估值冻结、到期后加仓/补保证金/保护/平仓、自动奖励、管理员权限、批次上限。

经明确授权的单用户活动撤回使用 `script/reset_forex_activity_user.rb`，不挂载到插件或 HTTP API。先预览范围及汇总金额，执行时锁定交易与账本，在同一事务中移除该用户活动外汇及补保证金流水、订单、持仓、关联通知和徽章，重算剩余流水的余额快照，恢复不可变触发器。只保留不含原始流水的完成摘要防止重复执行；遇到旧外汇仓位或不明资金流动会拒绝操作。隔离测试见 `test/forex_activity_reset_test.rb`。
