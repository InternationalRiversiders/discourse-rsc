# RSC 访问修复与非棋牌功能复核（2026-09-21）

> 后续补全、完整数据演练及最新验收见 [迁移补全记录](completion-2026-09-21.md)。本文中的较早待办与测试计数保留作历史记录。
本轮对照旧 RiversideCoin 的 wallet、exchange、worldCup、coinAdmin、rewards、admin 六组路由（81 个方法/路径组合，包含重复管理入口）、相应业务服务、原生插件及旧打赏主题。认证由论坛会话接管，不要求旧路径逐个照搬。下表区分功能存在、交互差异和真实上线验收；不能把测试通过写成全部迁移完毕。

## 本轮修复

1. 私有演示管理员 `rsc_admin` 有管理权限，但没有钱包使用组成员资格。普通账号的 `/rsc/state.json` 为 200，管理员为 403 / `membership_required`。共同侧栏选择管理入口本身符合权限；错误在于后台无条件提供“返回钱包”。
2. 所有钱包侧路由（钱包、股市、预测、排行、红包）遇到只有管理权限的账号，先转到后台，不再加载必然失败的 state 模型；后台对此类账号显示“返回论坛”和明确的权限说明。API 继续拒绝未授权钱包读取与资金操作。
3. 仅在独立演示库，将演示管理员加入现有测试使用组。它可测试钱包及后台，生产用户组没有改变。演示初始化脚本同步修正，避免再次生成不可测试钱包的管理员。
4. 奖励预览不再创建钱包；增加独立 GET 预览接口，查询参数 `pay=true` 也不会付款。只读站可预览，写入按钮禁用，原 POST 写保护保留。
5. 对照旧 `fetchDailyActivity` SQL，恢复业务日内 last_seen_at / previous_visit_at 的登录证明回退，避免仅查 user_visits 漏算；UTC+8 日界与每日 10 RSC 上限保持。今日卡片分列主题数和回复数。
6. 后台流通量及托管量采用与其他页面一致的金额截断展示。

## 当前结论

主要业务链路已有原生实现，可以继续在私有入口测试；**不能宣布除棋牌外所有细节已完整迁移，也不能据此接管真实资金**。除上表的页面与后台交互缺口外，生产接管仍需完成：持续行情与赛事/Sidekiq 验收、孤立资产归属、最终停写和最新快照全量对账、生产主题/插件组合与旧分享入口切换。旧 App 是否需要保留接口应依据实际调用，而不是默认所有旧路由必须保留。

本轮只更新私有测试入口，没有修改生产 Discourse YAML、旧 RSC 服务或真实资产。

验证结果和私有日志位于 `/opt/archives/migration-records/rsc-access-review`；本文件不包含密码、密钥或用户资产明细。
